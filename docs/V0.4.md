## Important implementation note

The included scheduler interprets a schedule as a daily cadence placeholder. A production implementation should use a real cron parser (for example cron-parser) and timezone-aware next-run calculation.

The webhook model is production-shaped, but the sample delivery implementation should be upgraded to decrypt integration secrets through the same KMS/secret-manager abstraction used by the API before enabling signed delivery at scale.

The crawler must call `assertSafeUrl()` before network requests and revalidate redirects. This is intentionally called out rather than pretending the V0.4 crawler is a complete SSRF boundary.
